# SEO Fixes (transfers-only launch) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task, **one implementer at a time**. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the staging SEO audit's blocking findings so transfers (TravelSugbo's transfers-only launch product) are actually indexable and found — `/transfer` indexable, a real per-route landing page per active route, international guest phone support, visible/actionable form-validation errors, correct meta lengths, a fixed mobile overlap bug, and friendlier admin settings copy — without touching money, auth, roles, sessions, or the site-wide noindex/robots launch gates.

**Architecture:** Every SEO decision stays where it already lives: `server/src/seo/resolvers.ts` (the one route→meta map, used by both the prod and dev injection surfaces) and `server/src/seo/sitemap.ts` (the one "indexable ⇒ in the sitemap" collector). New route landing pages are a new `ROUTES` entry plus a new client page, built from existing `transfer_routes`/`transfer_places`/`transfer_route_vehicle_prices` rows — no new tables, no new settings keys. Guest-phone internationalisation is one new shared Zod schema (`guestPhoneSchema`) that sits beside the existing `phPhoneSchema` (left untouched, still used by drivers/vans) and replaces it only on guest-facing inputs. Form-error visibility reuses the existing `lib/field-errors.ts` reader by adding one small, additive capability (reading a _local_, pre-submit Zod failure through the same API a server failure already uses) rather than inventing a second error pipeline.

**Tech Stack:** Existing stack only — React + TS + Vite + Tailwind v4 + shadcn/ui, Express + tRPC, Drizzle + MySQL 8, Zod (shared). No new libraries.

**Spec:** This plan's own brief (owner message, 2026-11-24) plus `CLAUDE.md`'s "SEO & indexing", "Checkout & payments", "Brand & design", and "DO NOT" sections, which this plan argues from throughout.

**Flag 2 — RESOLVED by owner decision 2026-11-24: one URL per DIRECTION.**
This plan's own Step 1 draft had proposed one canonical URL per route

near-identical pages differing only in travel direction risks the "thin

than templated filler. The reverse URL is DERIVED from the stored forward
slug (`reverseTransferRouteSlug()`, Task 8) rather than stored, so this
still required no schema change — the one piece of Flag 3's reasoning this
decision leaves untouched.

**Flag 3 — no schema change needed.** `transfer_routes` already carries

**Flag 4 — updated during execution: there is no guest-facing phone LOOKUP,

The brief asks that "the portal booking lookup... match the normalised value"
after `guestPhoneSchema` lands. `portal.login` and `checkout.bookingLookup`

```ts
/**
 * A guest's own contact number — unlike {@link phPhoneSchema} (drivers and
 * vans, PH-only by owner instruction), a GUEST may be an international
 * tourist with no PH SIM. Accepts every form `phPhoneSchema` does (PH local
 * `09XXXXXXXXX`, PH E.164 `+639XXXXXXXXX`) OR a general E.164 number: `+`,
 * a nonzero first digit, 6-14 more digits (7-15 digits total after the
 * `+`, matching the ITU E.164 ceiling). Spaces, dashes and brackets are
 * stripped first, exactly as `phPhoneSchema` already does, so a guest
 * typing their number the way they read it is never rejected for it.
 *
 * Normalises to E.164 exactly as `phPhoneSchema` does for the PH forms
 * (`0917...` -> `+63917...`); an already-`+`-prefixed number (PH or
 * international) is returned unchanged. This is deliberately the SAME
 * normalisation `phPhoneSchema` uses for its own two forms, so an old
 * `bookings.leadPhone` value written before this schema existed still
 * matches a guest retyping the identical PH number today.
 */
const INTERNATIONAL_PHONE_PATTERN = /^\+[1-9]\d{6,14}$/;

export function isLikelyInternationalPhone(raw: string): boolean {
  const stripped = raw.replace(/[\s()-]/g, '');
  return stripped.startsWith('+') && !stripped.startsWith('+63');
}

export const guestPhoneSchema = z
  .string()
  .transform((value) => value.replace(/[\s()-]/g, ''))
  .pipe(
    z
      .string()
      .refine(
        (value) => /^(09\d{9}|\+639\d{9})$/.test(value) || INTERNATIONAL_PHONE_PATTERN.test(value),
        'Enter a valid mobile number, like 0917 123 4567 or +1 555 123 4567.',
      ),
  )
  .transform((value) => (value.startsWith('+') ? value : `+63${value.slice(1)}`));

/** Shown as the phone field's placeholder on every guest-facing form. */
export const GUEST_PHONE_PLACEHOLDER = '09XX XXX XXXX or +1 555 123 4567';
```

```ts
import { z, type ZodError } from 'zod';

export interface FlattenedZodError {
  formErrors: string[];
  fieldErrors: Record<string, string[]>;
  nestedFieldErrors: Record<string, string[]>;
}

/**
 * BUG-120's dot-path flattener (originally `server/src/trpc.ts`'s private
 * `flatten()`), extracted here so the server's `errorFormatter` and a
 * client-side PRE-SUBMIT validation pass (`client/src/lib/field-errors.ts`)
 * read one formula instead of two that can drift. See `trpc.ts`'s own
 * comment for the server-only `scrubPaths` step this file deliberately does
 * not apply.
 */
export function flattenZodError(error: ZodError): FlattenedZodError {
  const flat = z.flattenError(error);

  const nestedFieldErrors: Record<string, string[]> = {};
  for (const issue of error.issues) {
    if (issue.path.length < 2) continue;
    const key = issue.path.join('.');
    (nestedFieldErrors[key] ??= []).push(issue.message);
  }

  return {
    formErrors: flat.formErrors,
    fieldErrors: Object.fromEntries(
      Object.entries(flat.fieldErrors).map(([k, v]) => [k, v ?? []]),
    ) as Record<string, string[]>,
    nestedFieldErrors,
  };
}
```

```ts
/**
 * A pre-submit failure found by validating a guest's own typed input
 * CLIENT-SIDE, against the exact same shared schema the server will run —

 * `{formErrors, fieldErrors, nestedFieldErrors}` shape a server's

 * (`getFieldErrors`, `getNestedFieldError`, `getFormErrors`,
 * `firstValidationMessage`) works on it unchanged — this is a second
 * PRODUCER of the shape those readers already consume, not a second shape.
 */
export class LocalValidationError extends Error {
  constructor(public readonly zodError: WireZodError) {
    super('Client-side validation failed.');
  }

/**
 * Validates `payload` against `schema`; returns a {@link LocalValidationError}
 * ready to hand to `getFieldErrors`/`getNestedFieldError`/`ErrorSummary`, or
 * `null` when the payload is valid. A form calls this BEFORE `mutate()` so an

export function clientSideErrors(schema: ZodType, payload: unknown): LocalValidationError | null {
  const result = schema.safeParse(payload);
  if (result.success) return null;

}
```

```ts
export function formatDurationMinutes(minutes: number): string {
  const h = Math.floor(minutes / 60);
  const m = minutes % 60;
  if (h === 0) return `${m} min`;
  if (m === 0) return `${h} hr`;
  return `${h} hr ${m} min`;
}

/**
 * Pattern matches GREEDILY on the first group, so a slug with more than one
 * "-to-" occurrence splits at the LAST one (`a-to-b-to-c` -> group1=`a-to-b`,
 * group2=`c`) — an accepted, documented edge case; every seeded slug has
 * exactly one occurrence.
 */
const FROM_TO_SLUG_PATTERN = /^(.+)-to-(.+)$/;

/**
 * Derives the OTHER direction's own public URL slug from a route's stored
 * (forward) `transfer_routes.slug` — no second column, no migration (owner
 * decision 2026-11-24, superseding this plan's original "one URL per route"
 * design). Every seeded slug already reads `{from}-to-{to}`, so swapping the
 * two halves produces the exact human-readable reverse URL the owner asked
 * for. A slug that does not contain the literal `-to-` segment (an admin
 * free-typed something else) falls back to a `-return` suffix instead of
 * guessing — still a real, distinct, valid URL, just a less descriptive one.
 */
export function reverseTransferRouteSlug(slug: string): string {
  const match = slug.match(FROM_TO_SLUG_PATTERN);
  if (!match) return `${slug}-return`;
  return `${match[2]}-to-${match[1]}`;
}
```

```ts
async function loadActiveTransferRouteRows(): Promise<ActiveTransferRouteBaseRow[]> {
  const db = getDb();
  const fromPlace = alias(transferPlaces, 'seoFromPlace');
  const toPlace = alias(transferPlaces, 'seoToPlace');

    .select({

      inclusionsText: transferRoutes.inclusionsText,
      exclusionsText: transferRoutes.exclusionsText,
      pricingMode: transferRoutes.pricingMode,
      minPayingPax: transferRoutes.minPayingPax,
      updatedAt: transferRoutes.updatedAt,
    })
    .from(transferRoutes)
    .innerJoin(fromPlace, eq(fromPlace.id, transferRoutes.fromPlaceId))
    .innerJoin(toPlace, eq(toPlace.id, transferRoutes.toPlaceId))

      and(
        eq(transferRoutes.isActive, true),
        eq(fromPlace.isActive, true),
        eq(toPlace.isActive, true),
      ),

async function finishTransferRouteSeoRow(
  row: ActiveTransferRouteBaseRow,
  direction: TransferDirection,
  requestedSlug: string,
): Promise<TransferRouteSeoRow> {
  const db = getDb();
  const priceRows = await db
    .select({ oneWayPriceCentavos: transferRouteVehiclePrices.oneWayPriceCentavos })
    .from(transferRouteVehiclePrices)
    .where(eq(transferRouteVehiclePrices.routeId, row.id));
  // Deliberately NOT filtered by current fleet sellability — see this
  // interface's own field comment above. Meta describes the catalog price
  // list, not a live dispatch fact.
  const cheapestOneWayCentavos =
    priceRows.length === 0 ? null : Math.min(...priceRows.map((p) => p.oneWayPriceCentavos));

  // The DROPOFF place for THIS direction owns the illustrative photo, if any.
  const dropoffDestinationId =
    direction === 'forward' ? row.toPlaceDestinationId : row.fromPlaceDestinationId;
  const imagePath =
    dropoffDestinationId === null
      ? null
      : ((
          await db
            .select({ imagePath: destinations.imagePath })
            .from(destinations)
            .where(eq(destinations.id, dropoffDestinationId))
        )[0]?.imagePath ?? null);

  return {
    id: row.id,
    slug: requestedSlug,
    direction,
    fromPlaceName: direction === 'forward' ? row.fromPlaceName : row.toPlaceName,
    fromPlaceType: direction === 'forward' ? row.fromPlaceType : row.toPlaceType,
    toPlaceName: direction === 'forward' ? row.toPlaceName : row.fromPlaceName,
    toPlaceType: direction === 'forward' ? row.toPlaceType : row.fromPlaceType,
    reverseEnabled: row.reverseEnabled,
    estimatedDurationMinutes: row.estimatedDurationMinutes,
    freeCancelHours: row.freeCancelHours,
    inclusionsText: row.inclusionsText,
    exclusionsText: row.exclusionsText,
    pricingMode: row.pricingMode,
    minPayingPax: row.minPayingPax,
    updatedAt: row.updatedAt,
    cheapestOneWayCentavos,
    imagePath,
  };
}

/**
 * Tries a FORWARD match (`transfer_routes.slug === requestedSlug`) first,
 * then a REVERSE one (`reverseTransferRouteSlug(route.slug) ===
 * requestedSlug`, and only among `reverseEnabled` routes) — the forward slug
 * is the stored, admin-chosen identity; the reverse slug is derived and
 * never stored, so it cannot be looked up by an indexed `WHERE` and is
 * matched in JS against the same small active-route scan the sitemap uses.
 */
export async function loadTransferRouteSeo(
  requestedSlug: string,
): Promise<TransferRouteSeoRow | null> {
  const rows = await loadActiveTransferRouteRows();

  const forwardMatch = rows.find((r) => r.slug === requestedSlug);
  if (forwardMatch) return finishTransferRouteSeoRow(forwardMatch, 'forward', requestedSlug);

  const reverseMatch = rows.find(
    (r) => r.reverseEnabled && reverseTransferRouteSlug(r.slug) === requestedSlug,
  );
  if (reverseMatch) return finishTransferRouteSeoRow(reverseMatch, 'reverse', requestedSlug);

  return null;
}
```

```ts
export function transferRouteTitle(
  route: Pick<TransferRouteSeoRow, 'fromPlaceName' | 'toPlaceName' | 'cheapestOneWayCentavos'>,
): string {
  const price =
    route.cheapestOneWayCentavos === null ? null : formatPeso(route.cheapestOneWayCentavos);
  const candidates = [
    price &&
      `${route.fromPlaceName} to ${route.toPlaceName} Private Transfer — from ${price} | ${BRAND}`,
    `${route.fromPlaceName} to ${route.toPlaceName} Private Transfer | ${BRAND}`,
    price && `${route.fromPlaceName} to ${route.toPlaceName} Transfer — from ${price}`,
    `${route.fromPlaceName} to ${route.toPlaceName} Transfer`,
  ].filter((c): c is string => Boolean(c));
```

```tsx
interface RouteDirectionView {
  route: TransferRoutePublicRow;
  direction: TransferDirection;
  pickupPlace: TransferRoutePublicRow['fromPlace'];
  dropoffPlace: TransferRoutePublicRow['toPlace'];
  pageTitle: string | null;
  /** This direction's OWN URL slug (echoes the requested param, always). */
  slug: string;
  /** The OTHER direction's slug, present only when `reverseEnabled`. */
  otherSlug: string | null;
}

/**
 * Tries a FORWARD match (`route.slug === requestedSlug`), then a REVERSE one
 * — the SAME two-step order and the SAME pure `reverseTransferRouteSlug`
 * `loadTransferRouteSeo` (Task 8) uses server-side, so a slug this page
 * accepts is never one the server's resolver would have 404'd, and vice
 * versa. A reverse match against a `reverseEnabled: false` route is
 * impossible by construction (the filter below), mirroring the server.
 */
function matchRouteDirection(
  routes: TransferRoutePublicRow[],
  requestedSlug: string,
): RouteDirectionView | null {
  const forward = routes.find((r) => r.slug === requestedSlug);
  if (forward) {
    return {
      route: forward,
      direction: 'forward',
      pickupPlace: forward.fromPlace,
      dropoffPlace: forward.toPlace,
      pageTitle: forward.pageTitle,
      slug: requestedSlug,
      otherSlug: forward.reverseEnabled ? reverseTransferRouteSlug(forward.slug) : null,
    };
  }

  const reverse = routes.find(
    (r) => r.reverseEnabled && reverseTransferRouteSlug(r.slug) === requestedSlug,
  );
  if (reverse) {
    return {
      route: reverse,
      direction: 'reverse',
      pickupPlace: reverse.toPlace,
      dropoffPlace: reverse.fromPlace,
      pageTitle: reverse.reversePageTitle,
      slug: requestedSlug,
      otherSlug: reverse.slug,
    };
  }

  return null;
}

function cheapestOffer(route: TransferRoutePublicRow) {
  return (
    route.vehiclePrices.slice().sort((a, b) => a.oneWayPriceCentavos - b.oneWayPriceCentavos)[0] ??
    null

}

    return 'Your driver meets you at the arrivals area with a name sign. Tell us your flight number and airline when you book so your driver can time your pickup around your actual arrival.';

    return "We'll ask for your ferry name and arrival time when you book, so your driver is waiting when you dock.";
  }
  return null;
}

  dropoffType: TransferRoutePublicRow['toPlace']['placeType'],
): string | null {
  if (dropoffType === 'airport') {
    return 'We pick you up from your hotel or accommodation. Tell us your flight number and departure time when you book so we can plan a pickup that gets you to the airport with time to check in.';
  }
  if (dropoffType === 'pier') {
    return "We'll drop you right at the pier in time for your ferry — tell us your departure time when you book.";
```

```ts
const HERO_FORM_SELECTORS = [
  'form[aria-label="Find a transfer"]',
  'form[aria-label="Search tours"]',
];

function useCoversHeroSearch(pathname: string): boolean {
  const [covers, setCovers] = useState(false);

  useEffect(() => {
    if (typeof IntersectionObserver === 'undefined') return;

    const targets = HERO_FORM_SELECTORS.map((sel) => document.querySelector(sel)).filter(
      (el): el is Element => el !== null,
    );
    if (targets.length === 0) {
      setCovers(false);
      return;
    }

    // Track each target's own intersecting state (IntersectionObserver's
    // callback only reports entries that CHANGED since the last call, so a
    // single boolean cannot be derived from one callback invocation alone
    // when there is more than one observed target).
    const intersecting = new Set<Element>();
    const observer = new IntersectionObserver((entries) => {
      for (const entry of entries) {
        if (entry.isIntersecting) intersecting.add(entry.target);
        else intersecting.delete(entry.target);
      }
      setCovers(intersecting.size > 0);
    });
    targets.forEach((t) => observer.observe(t));
    return () => observer.disconnect();
  }, [pathname]);

  return covers;
}
```

```ts
/**
 * Fires a GA4 custom event (and, when the Pixel is also installed, a
 * matching Meta `trackCustom`). Both are already consent-gated at the
 * INSTALL step (`injectGA4`/`injectMetaPixel` only ever run post-consent, per

export function trackEvent(name: string, params: Record<string, unknown> = {}): void {
  if (typeof window.gtag === 'function') window.gtag('event', name, params);
  if (typeof window.fbq === 'function') window.fbq('trackCustom', name, params);
```

```ts
export function phoneWhatsappLink(e164: string, message?: string): string {
  const digits = e164.replace(/^\+/, '');
  const base = `https://wa.me/${digits}`;
  return message ? `${base}?text=${encodeURIComponent(message)}` : base;
}

export function phoneViberLink(e164: string): string {
```
