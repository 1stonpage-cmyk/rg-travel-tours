# Week 7 — Public tour pages, admin editing, reports, reviews Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the gap between a guest seeing a tour and a guest booking it, then give the owner screens to edit the content, prices, coupons, settings and reviews that today are editable only by SQL — plus reports over real money, and the deferred fixes Week 6.5 handed forward.

**Architecture:** The public tour pages are almost entirely client work: `tours.list`, `tours.bySlug`, `checkout.quote` and `checkout.availability` already exist, tested, and the SEO resolvers already answer `/tours` and `/tours/:slug`. The admin editing screens are the first write paths into `tours`, `coupons` and `settings` outside the seed, each behind the `adminProcedure(area)` gate that already carries the right ROLE_MATRIX rows. Reports read money and never write it.

**Tech Stack:** React + TypeScript + Vite + Tailwind v4 + shadcn/ui + React Router · Express + tRPC · Drizzle + MySQL 8 · Zod (shared) · nodemailer · node-cron. No new libraries.

**Spec:** `docs/BUILD_SPEC.md` — §4 (public website), §5 (pricing), §9 (admin & roles), §11 (notifications), §13 Week 7. The spec wins any disagreement with this plan.

**Base commit:** `5bb904e` on `main`.

## Global Constraints

Every task's requirements implicitly include this section. Copied from `CLAUDE.md` and the owner's prompt of 2026-10-23.

- **Money is integers in centavos** everywhere — database, API, logic. Format only at display, via `formatPeso` from `@rg/shared`.
- **The server computes all money.** Never trust a price, total, deposit or discount sent from the browser. The tour detail page's live price summary calls `checkout.quote`; it does no arithmetic of its own.
- **`bookings.amount_paid_centavos` is written only by `recordPayment` and `verifyPendingManualPayment`** in `server/src/services/payments/record-payment.ts`. The allow-list is `CREDITING_FUNCTIONS` in `server/src/__tests__/schema-conventions.test.ts`; adding a third crediting function means adding an entry in the same commit. **No task in this week adds one.**
- **A refund is never a subtraction.** It is a separate positive `payments` row with `type = 'refund'`, `status = 'refunded'`. It never decrements `amount_paid_centavos`.
- **Never hard-delete bookings or payments.** Tours, vans, drivers, users, coupons and reviews are soft-deleted via `is_active` / `status`.
- **`audit_log` for every money movement, status change and assignment.** Reports and read-only screens write no audit rows.
- **NO RED anywhere**, including test titles. Errors use `brand-error` (`#334155`), warnings amber. `client/src/__tests__/no-red.test.ts` and `contrast.test.ts` are the guards. `brand-gold-600` fails AA for small text — use `brand-gold-700` or darker.
- **Mobile-first at 360px**, 44px tap targets, visible focus, alt text on every image, AA contrast.
- **Store UTC, display and compute business dates in Asia/Manila.** Convert with `civilDateFromDate()` / `manilaCivilDate()`; compare `date()` columns with the raw-`sql` helpers (`on()`, `onDate()`, `betweenDates()`), never `eq()` against a string.
- **Time-dependent queries take an explicit `now`.** No clock reads inside a service or a query.
- **Zod on every input**, schemas shared from `/shared`.
- **Every admin procedure is an `adminProcedure(area)`** from `server/src/trpc.ts`. Never a hand-rolled role check. Hiding a button is not access control.
- **No new npm libraries** without asking.
- **Ports 5180 (client) and 3100 (server).** Never 5173 or 3000.
- **Never touch Kong PMS** (its files, its database, ports 5173/3000/3111, the `kongpms` service), production, or the VPS. **Never touch `C:\dev\travelsugbo-explainer`.** Do not push.
- **Every task:** write `✅ DONE` immediately after it finishes · its own commit (`git add` of specific files, never `--amend`) · all five checks with exit codes — `pnpm lint` · `pnpm typecheck` · `pnpm test` · `pnpm format:check` · `ALLOW_PLACEHOLDER_BUILD=1 pnpm build` · every new test proven able to fail (break the code, see red, restore) · the leak detector silent · a browser check at `http://localhost:5180` at 1440px and 360px.

## The four things this week must not get wrong

1. **A price on the public tour detail page must come from `checkout.quote`.** The page has `priceTiers` in its payload and it would be one line to multiply them — that line is the bug the money rule exists to prevent. The tiers render as a _table of what the tiers are_; the live summary for the chosen date and party size is the server's answer.
2. **A sitemap must never list a URL that says `noindex`, and an indexable URL must be in the sitemap.** `buildDetailUrls` emits tours and packages in one array. Task 2 releases the tours half only, by splitting that function. Releasing packages before `/packages/:slug` renders would put a correct-meta, empty-body page into Google.
3. **Narrowing receipt access is a role change, not a UI change.** Task 4 restricts `GET /api/receipts/:name`; the booking-detail link at `AdminBookingDetailPage.tsx:263` is a _second_ surface a dispatcher reaches it from, and hiding that link is cosmetic. The route is the guard.
4. **The lockout fix must not become a PIN-guessing hole.** Today the only way to clear `requires_admin_unlock` is `drivers.resetPin` (`server/src/routers/admin/drivers.ts:493`), which issues a **new PIN** — so "unlock the driver" currently means "change their PIN mid-shift". Any option in Q1 has to answer both halves: a prankster cannot park a driver, and a guesser still cannot walk the PIN space.

### Task 20 — 7P: booking refs are case-insensitive on lookup (BUG-108)

**Added by owner 2026-10-23 (Q10).** In scope this week for the same reason as Task 19 — more guests reaching checkout by hand-typing a ref from an email.

**Owner decision:** booking refs are case-insensitive on lookup, normalised to uppercase on the server. Refs are still **generated** uppercase — nothing about `generateBookingRef()` changes.

**Files:** Modify `shared/src/checkout.ts` (`bookingLookupInput`, and the `bookingRefSchema` the other two procedures use), `server/src/routers/public/checkout.ts` (`startPaymentInput`, `bookingStatusInput`, `bookingLookup`) · Test `server/src/__tests__/booking-ref.test.ts`, `server/src/__tests__/checkout-lookup.test.ts`

**Model:** Sonnet · **Schema:** no · **Touches money:** no · **Review:** combined

**The bug, exactly (BUG-108):** `bookingLookupInput` takes `z.string().min(1).max(12)` — anything that length, no case rule — while `startPaymentInput` and `bookingStatusInput` take `bookingRefSchema`, an **uppercase-only** regex. **The fix.** Add `normalizeBookingRef(ref: string): string` to `shared/src/checkout.ts` — trim, then uppercase. The query itself needs no change: it already receives a correctly-shaped uppercase ref, and the collation that made the third procedure work becomes true by construction instead of by accident.
