# Bugs Log — TravelSugbo / R&G Travel & Tours

Every defect found on this project, including ones caught in planning or review
**before they shipped**. A bug that was caught by a review still belongs here — the
point of the log is to show where defects come from, not only which ones escaped.

**Keep this updated.** Append a row when a bug is found; update its status when it is
fixed. One row per bug.

**Severity:** `critical` = data loss, a security control that does not work, or a
production outage. `important` = wrong behaviour, a missed requirement, or a test that
cannot fail. `minor` = polish, coverage gaps, and cosmetics.

**How found** is the most useful column over time. So far: `review` dominates, which is
the process working; `controller` entries are ones caught by verifying claims against
live data rather than reading a report; `plan` entries are defects in the implementation
plan itself, several of which would have shipped as "passing" code.

## Notes

- **Review found 17 of the 25 shipped-code bugs**, including all four criticals. The
  controller found 4 by verifying claims against live data rather than reading reports
  (BUG-002, BUG-014, BUG-023, BUG-031). Implementers self-reported 2 (BUG-018, BUG-041).
- **Four bugs were tests that could not fail** (BUG-012, BUG-016, BUG-020, and the
  vacuous credential-leak assertion fixed in `270a6d3`). Each would have reported green
  forever. This is the single most common defect shape on this project so far.
- **Two bugs were security controls that failed open** (BUG-018, BUG-019) and two were
  destructive operations missing a guard (BUG-009, BUG-010). All four were in code whose
  tests passed.
